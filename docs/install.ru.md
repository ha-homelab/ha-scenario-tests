# Установка и изоляция

Используйте Python 3.14.2–3.14.x и отдельную среду. Установите `requirements.lock` с `--require-hashes`, затем пакет с `--no-deps .`, как показано в README. Lock содержит зависимости приложения и тестов. Не устанавливайте инструмент в среду рабочего HA. При разработке используйте `pip install --no-deps -e .`.

Сначала `ha-scenario validate examples/stale_sensor.json`: проверка не импортирует HA. Затем `ha-scenario run examples/stale_sensor.json --report result.json`. Адрес сервера не настраивается. Выходной путь задаётся аргументом CLI, не содержимым сценария.

Дополнительная сетевая граница:

```sh
docker build -t ha-scenario-tests .
docker run --rm --network none --read-only --tmpfs /tmp:rw,nosuid,size=64m ha-scenario-tests
```

Сборке нужна сеть для зависимостей. Выполнение не имеет сети; запись разрешена только во временный `/tmp`. Не монтируйте реальные настройки, Docker socket и ключи. Это необязательный рецепт; факт проверки конкретного контейнера указан отдельно в validation record.

Дочерний Python `-I` получает только PATH, SYSTEMROOT, LANG и фиксированный hash seed. Токены и PYTHONPATH не наследуются. Родитель ограничивает выполнение 30 секундами, внутренний таймаут — 20 секунд. Сумма пауз не превышает 5 секунд, команд — 256. Зависшую нативную зависимость остановит родитель.

Pytest plugin устанавливается вместе с пакетом. Fixture `scenario_runner` принимает словарь сценария, возвращает отчёт; JUnit создаётся самим pytest. Для обычного Python доступен `run_scenario`.
