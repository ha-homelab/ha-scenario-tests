# Диагностика

- Код 2: проверьте Python 3.14.2–3.14.x, точную версию HA и чистую среду. Другие версии HA отклоняются.
- Worker failure/timeout: зависимость или инициализация HA завершилась ошибкой. Локальную трассировку получите только с синтетическим файлом: `python -I -m ha_scenario_tests.worker < examples/presence_timeout.json`. Не публикуйте непроверенные сведения среды.
- calls_mismatch: сравните порядок и повторения команд. Состояние seed установлено до запуска и не обязано вызывать новый state trigger.
- forbidden_call: движок отправил запрещённую команду тестовому исполнителю. Физическое устройство не участвовало.
- states_mismatch: итоговое состояние отличается из-за действия или шага timeline.
- blocked_io/background_exception: не отключайте защиту ради зелёного теста. Передайте синтетический пример и версию.
- Нестабильный таймер: увеличьте запас между переходом и сроком. Это настоящий event loop, не виртуальные часы.
- Reload: настоящий reload может отменить for-таймер. Если политика требует восстановления, нужна явная reconciliation-автоматизация; пример reload_reconcile.json.
- Уже существующий отчёт: выберите новый путь, перезапись запрещена.

При обычной установке переустановите пакет после правки исходников. Для разработки удобнее `--no-deps -e .`.
